# Printed blocks and the 3D printer

The source of behavior is MightyPirates/OpenComputers commit `258943363ea8fc4ef14948e6bc6f67375061580c`: `common/tileentity/{Print,Printer}.scala`, `common/block/{Print,Printer}.scala`, `common/item/data/PrintData.scala`, the original inventory/redstone/rotation and custom-drop traits, the common block item, `common/container/Printer.scala`, `client/renderer/block/{PrintModel,SmartBlockModelBase}.scala`, and `client/renderer/tileentity/PrinterRenderer.scala`. Existing registered assets, original attribution and model-performance work remain in place.

The `printer3d` component builds independent off/on shape collections. Coordinates clamp to 0–16, Z is inverted as in the source, empty shapes fail, texture names and labels/tooltips retain their original length limits, and tint can occupy either optional argument position. Repeated geometrically equal shapes remain separate entries, as in the source's reference-based shape set. Shape serialization uses the original deterministic ordering. Model costs count both states' voxel volumes and surface areas, apply the custom-redstone surcharge and noclip multiplier, and preserve recycling and cartridge/dye provider values.

The original callback descriptions and validation order are restored. Collision arguments are checked together before either state changes. Configuration edits cancel future queued jobs while the current captured output completes; changing collision flags preserves the original no-uncommit behavior. Printer work retains the source's minimum one-energy request for newly started or unfinished pieces, including the final fractional request. The existing completed-output correction is retained: a full compatible output slot may finish the current piece, then waits without further energy spending, material consumption or input conversion. Output remains the captured item rather than being replaced by subsequent template edits.

The three-slot inventory keeps the original material/ink/output validation and sided extraction semantics. Modern registry-aware saves retain material/ink amounts, template, queue/limit, captured output, node identity and remaining energy. Legacy `ManagedEnvironment.load/save` now delegate to the actual world's registries, and world inventory loading also accepts the original `oc:items` representation. The menu retains the original slot locations, inventory layout and progress/material/ink values. The printer has its original player tooltip, enchantment exclusion, bottom-only support, non-spawnable surface and nonsneaking GUI activation.

Printed blocks retain per-shape collision/ray geometry, optional noclip by state, single-shape face support, approximate configured opacity, constant configured light emission, off/on redstone behavior, lever sounds, horizontal scrench rotation and 20-tick button return. The public `Rotatable` marker exposes their orientation. Placement initializes the six redstone samples after installing the actual model; saved input history remains independent from client updates. Drops and pick-block carry the model data rather than active redstone state. Beacon-base and light crafting operations continue to preserve template data, and the narrow beacon scan mixin supplies the modern equivalent of the old per-instance beacon-base hook.

The pinned version contains no ladder behavior. Its `pressurePlate` flag is serialized but has no collision/tick interaction handler. Those fields are preserved without adding a new mechanic.

The original texture fallback, cube-mapped UVs, packed tint, off/on item rendering, empty-item lime preview and 20-second rotating printer preview remain. Item preview state now follows the player's configured sneak binding rather than hardcoded Shift. The finite Windows visual acceptance should inspect one asymmetric two-state textured/tinted print, its item preview with the rebound sneak key, and the printer's rotating preview/menu; it belongs to the shared client acceptance scope.

`PrintingContract` uses actual Case contexts, a physical printer, normal material/ink inputs and actual generated printed items. Its bounded server scenario checks template/cost/queue operation, blocked-output waiting and resumption, public save/load, and printed-world interaction/geometry/redstone/drop behavior. It does not stand in for the shared client rendering/menu or multiplayer acceptance.

Windows NeoForge 21.1.224 run `systems-20261027-f4` passed every `printing.*` scenario: actual material/cartridge/dye conversion, exact model costs, two powered jobs, compatible full-output waiting without extra charges, captured pending-output save/load/reset, normal recipe upgrades and actual printed-world collision/support/light/redstone/button behavior. A real beacon reached level one above the generated model, and actual survival drops retained its data. The full-slot fixture copies the first genuinely printed item to its ordinary stack limit; the second output is still produced by the printer with real costs. The report is `build/api-compat-addon/devices/systems-20261027-f4/device-results.txt`. Its unrelated screen-fixture assertion was corrected and passed separately in f5 with the same production build.
