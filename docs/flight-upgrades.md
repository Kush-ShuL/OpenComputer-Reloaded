# 天使与悬浮升级

语义来源仅为 MightyPirates/OpenComputers 固定提交
`258943363ea8fc4ef14948e6bc6f67375061580c`：`UpgradeAngel.scala`、
`UpgradeHover.scala`、对应物品和驱动、`AngelUpgradeHandler.scala`、
`RobotCommonHandler.scala`，以及 `Agent.scala` 的空中交互分支。
保留上游许可证和归属，使用 Java 实现。

D41 天使升级是二级升级，保留普通网络节点，既无 Lua 回调，也无独立能量连接器。
设备型号为 `FreePlacer (TM)`，`capacity` 沿用原版的 `maxNetworkPacketSize`。
空中放置事件根据机器人或无人机机器节点可到达的天使升级，明确设置允许或拒绝；
原宿主黑名单拒绝适配器、微控制器和平板，允许无人机。`place` 与无射线命中时的
`use` 均经过原空中放置事件，实际放置继续使用正常方块和物品交互入口。
参照由从宿主外表面开始的射线命中决定，不把机器人自身或目标附近任意方块当作参照。
未指定点击面时依次尝试前方及四个侧面；指定背向面的参数按原版拒绝。
`place` 使用选中背包槽，空中目标必须可替换且没有实体；`use` 的空中分支按原版先
尝试主背包第一槽，再尝试装备物品，最后执行装备物品的普通使用动作。临时供料槽
同时读写该真实槽位，不改变玩家的选中槽，物品操作结束后恢复手持路由。
实际放置保留原放置前后事件与 NeoForge 物品放置入口；`place` 不会激活参照方块。
`use` 保留方块激活、物品放置、物品使用和实体交互的不同结果。
升级没有额外耗能、动作延迟或自定义持久状态，沿用宿主动作的费用和延迟。

T07 悬浮升级有一级、二级两种，物品提示显示各自 `robot.upgradeFlightHeight`，
不创建组件环境或 Lua 回调。机器人移动事件从装备槽及内置组件取得所有悬浮升级，
与 `robot.limitFlightHeight` 取最大高度，多件不会相加。基础限制为负时关闭限制。
以下任一条件成立即允许移动：

- 世界方向为向下。
- 最大悬浮高度达到世界总高度。
- 起点或目标的任意邻接方块，朝向该位置的面可支撑。
- 起点下方一至最大悬浮高度内至少有一个非空气方块。

其余移动取消。下方检查沿用原版只扫描起点、不要求该方块有完整顶面；邻接检查则
要求朝内的支撑面。悬浮升级不另扣能量、不改变正常移动延迟，无自定义持久状态。
当前移动处理已经实现上述规则，无需重写。

天使设备信息、空中交互、共享事件的节点可达性与明确允许/拒绝、无人机宿主许可
均已接入；悬浮升级的固定源码范围已匹配。主模组 Windows 构建通过。

Windows NeoForge 21.1.224 批次 `agent-actions-20261027-b2` 用两台原创造配置
机器人验证了五项真实交互：无天使时 `place` / `use` 拒绝纯空气且不扣料；
有天使时 `place` 从选中槽扣一件；`use` 从主背包第一槽扣一件，保持实际选中槽
和装备物品；无天使时有真实方块射线命中的普通放置仍成功。
每项直接核对实际世界方块、库存数量和选中槽，未启动固件或替换 BIOS。
