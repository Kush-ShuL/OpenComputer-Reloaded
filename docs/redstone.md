# Redstone cards and external I/O

Behavior follows MightyPirates/OpenComputers commit `258943363ea8fc4ef14948e6bc6f67375061580c`, including `RedstoneVanilla`, `RedstoneBundled`, `RedstoneSignaller`, the redstone-aware host traits and original driver/item/block behavior. The existing sixteen-channel state is shared by cards, external I/O and optional providers. The vanilla provider also makes advanced callbacks available without installing another mod, as in the source.

Single-side callbacks use host-local directions. The six-side input/output result tables retain world axes; bulk assignment tables use local keys. Raw output integers remain unclamped in storage and callback results. The world exposes nonnegative output. Changed assignments apply the configured delay, while unchanged assignments do not. First input sampling suppresses startup events, subsequent changes report local sides and optional channel numbers, and upward threshold crossings wake neighboring machines for internal cards or the reachable network for external I/O.

The pinned no-side `getBundledOutput()` exposes the raw bundled **input** matrix. The all-side `setBundledOutput(table)` also returns that previous input matrix. These observable source quirks are retained; per-side/per-color output getters and physical output providers continue to use actual output. Input merges ordinary bundled and RedNet channel values. Saved host state preserves the separate input/output matrices, and card state preserves identity and wake threshold. Wireless callbacks belong to the separately tracked WRCBE integration.

The external block keeps its original description and disallows mob spawning. Cards retain the original description, short address, tier indicator and book-enchantment restriction. Rendering and remote player acceptance are tracked under the shared client/multiplayer requirements.

`RedstoneComputerCraftContract` uses actual world blocks, both real card drivers and the placed Case's own machine Context. Its finite scenario covers callback tiers, local/world axes, table keys, comparator input, physical signals, wakeup events, save/load identity and threshold, a real CC generic chest inventory, and a CC Lua computer booted from a physical disk to exchange sixteen-channel masks. The CC bridge must be explicitly enabled in this isolated fixture; normal installations remain disabled by default.
