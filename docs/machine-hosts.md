# Machine hosts

The adapter, computer cases, rack and server blades follow MightyPirates/OpenComputers commit `258943363ea8fc4ef14948e6bc6f67375061580c`. Their principal source files are `common/tileentity/{Adapter,Case,Rack}.scala`, `server/component/Server.scala`, the corresponding block and item classes, `common/inventory/{ComponentInventory,ServerInventory}.scala`, and `common/tileentity/traits/{Computer,OpenSides}.scala`.

Cases retain the original tier layouts and ownership checks. Agent interaction uses the agent owner's name, and client interaction uses the synchronized user list. Forge Energy enters the connected network's available buffer, subject to the case input rate and closed front face. A retained energy capability also checks the current front face. Creative cases retain their original periodic refill behavior. Removing a CPU stops its machine; adding one does not stop it. Floppy insertion and removal use the original sounds.

Adapters retain independent enable flags for the six adapted neighbors and a single upgrade slot. Removing an adapted neighbor first disconnects it from the adapter, then saves and removes it. Upgrade removal preserves the existing remove-before-save ordering. This ordering closes filesystem resources before the actual removed item receives its persisted component data.

Cases, adapter upgrades and blade components now deliver the original construction and removal lifecycle callbacks. Actual component removal disconnects the node before saving the removed stack, removes any node rejoined during saving, and then completes disposal. Breaking a case or rack prepares its mounted components before vanilla copies their dropped items. Removing a whole blade closes its machine and nested components before the rack saves the removed blade. Chunk unload and cold persistence retain their existing paths.

Blade inventory validation and environment creation query the public `li.cil.oc.api.internal.Server` marker. Components still receive the rack as their environment host, as in the original implementation. This allows external `HostAware` drivers to recognize blade slots without depending on implementation classes. Blade menu access follows physical rack access rather than the machine's computer-user list. Server items retain the original component summary on the configured sneak key, network-address hint, rarity and single-item stack limit. Component buses retain their tier tooltip and address-sensitive stack limit.

Rack wiring continues to use four isolated mountable slots, five external buses and the original primary/secondary connection mappings. The rack sends only redacted mountable item views and public mountable data to clients. Client views permit the original two-sided `onActivate` dispatch without joining networks, constructing machines or loading private VM state. Empty or non-analyzable front slots preserve the original null analysis result. Sneaking bypasses ordinary case/adapter/rack menus except for mountable-specific interactions.

The existing separate-process native Case and Rack/Server persistence checks remain applicable: they cover VM, EEPROM, hardware, node identities and isolated rack buses across a saved-world restart. The finite `MachineHostsContract` scenario covers the new hot-removal/lifecycle, public server marker and case-to-network energy paths. It does not replace multiplayer permissions, client visual interaction or the existing cold persistence checks.
