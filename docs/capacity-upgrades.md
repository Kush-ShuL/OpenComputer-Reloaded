# 物品栏升级与组件总线

依据 MightyPirates/OpenComputers 固定提交 `258943363ea8fc4ef14948e6bc6f67375061580c` 的 `DriverUpgradeInventory.scala`、`DriverComponentBus.scala`、机器人/无人机容量计算与服务器槽位表（MIT 许可证）。

物品栏升级是一级升级，占用升级槽，单个提供 16 格机器人空间。它没有组件节点，也不提供可热插拔物品槽。多件升级的容量相加，机器人总空间上限为 `96 - 内置组件数量`。无人机按每件库存驱动的 `max(1, 容量 / 4)` 计算，最多 8 格，因此一个普通物品栏升级提供 4 格，两个提供 8 格。

拆除升级导致容量缩小时，机器人先将越界物品尝试合并回保留的库存，再向正面掉落剩余物品，并限制选中槽位到新范围。现代适配会在掉落实体被取消时保留剩余物品，避免物品消失。物品栏升级遵循原主机黑名单：禁止适配器、微控制器和平板，同时保留其他模组通过 IMC 注册的限制；兼容的自定义宿主不被额外排除。

| 组件总线 | 安装等级 | 默认增加的组件容量 |
| --- | --- | --- |
| 一级 | 1 | 8 |
| 二级 | 2 | 12 |
| 三级 | 3 | 16 |
| 创造 | 3 | 1024 |

总线容量读取 `computer.cpuComponentCount` 的四个值。创造总线保留第四项容量，但其安装等级降为三级，以便进入三级槽。总线实现 `Processor` 容量接口，架构和环境均为空；它增加 CPU 的组件容量，不代替 CPU、不增加调用预算，也不产生额外网络节点。

现有生产链已包括：服务器槽位等级验证、`Machine.onHostChanged()` 累加 CPU 与总线容量、只从 CPU 槽选择架构，以及总线拆装后的服务器容量重算。组件数超限仍通过机器的原有组件溢出错误处理。服务器一级有一个二级总线槽，二级有两个三级总线槽，三级及创造服务器有三个三级总线槽。

库存升级已与槽容器驱动分离，机器人溢出恢复已接入卸载回调和服务器 tick。
无人机容量、驱动注册及组件总线的现有消费链均已接入。Windows 构建和本批设备回归通过。
