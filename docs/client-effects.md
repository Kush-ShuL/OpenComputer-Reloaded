# 客户端效果与声音

机箱和机器人开机后会播放持续运行声，停机后停止。机器人移动时沿用同一个声源并更新位置。声音随“方块”音量、主音量和暂停状态变化；微控制器沿用原版的静音行为。

实现依据 MightyPirates/OpenComputers 提交 `258943363ea8fc4ef14948e6bc6f67375061580c` 的 `client/Sound.scala`、`common/tileentity/traits/Computer.scala`、`Robot.scala` 和 `Microcontroller.scala`。运行声使用 `computer_running`，音量为 `0.5 × client.soundVolume`；运行状态变化后的启动延迟为 50–99ms，初次载入正在运行的设备时为 1000–2999ms。

`ComputerSounds` 从客户端已同步的运行状态维护声源。机器人以稳定宿主关联移动前后的方块代理。源码已接入停机、设备移除、区块卸载、世界退出和声音引擎重载的生命周期。`SoundEngineMixin` 在声音 tick 完成后定向清理本模组运行声的失效索引和重复登记，避免反复静音恢复积累 ticking 条目。

Windows 客户端实测报告：`build/api-compat-addon/integration-client/client-sound-20261027-h2/client-results.txt`，整体状态 **PASS**。本批通过真实声音引擎及其声道验证：

- 真实机箱和机器人运行原生 Lua 固件后，启动循环声并使用配置对应的音量。
- 真实机器人移动后，同一声音实例更新位置，播放次数没有增加。
- 机箱停机释放声道，重新开机建立新的运行声。
- 连续三轮方块音量归零和恢复，真实声道均停止并恢复；每轮检查原生声音表，当前机箱和机器人各只有一条 ticking 与声源登记，已停止的旧机箱声源没有 ticking、删除计时或声源索引残留。
- 真实暂停菜单使运行声静音，返回游戏后恢复；声音引擎重载后重新建立声道。
- 实际移除测试方块后，客户端设备消失，运行声道释放。

上述证据验证声音的原生生命周期，不代表已经人工确认听感。真实区块卸载、世界退出和远程多人场景仍需对应玩家验收。

软盘插拔声由 `DiskSounds` 恢复原版链路：同一宿主的同一种声音有 500ms 冷却，广播范围为 `15 × client.soundVolume`，客户端播放音量为 `range / 15 + 0.5`。其中 15 表示范围，不能直接作为播放音量。机箱、外置软盘驱动器、机架式软盘驱动器和机器人软盘装备槽已接入；同一机架内的驱动器共享机架宿主的冷却。这部分依据原 `common/Sound.scala`、服务端 `PacketSender.sendSound` 和客户端 `PacketHandler.onSoundEffect`，实际外置驱动器插拔验证见下文。

C22 的闭合依据由循环声、其他客户端效果和机器人标签三批实际证据共同组成，不能仅凭循环声结果判断。现有 `UpdateChecker` 区分玩家模组发行与空 SDK/API 发行，实际登录检查见下文。

其他路径由独立的 EffectsClientContract 进行有限客户端实操，循环声复用上述 h2 结果：

- 外置软盘真实插拔经过服务器广播和原生声音事件，验证同宿主的 500ms 冷却、两种声音分别计时、范围和音量。真实调试卡剪贴板载荷作为同一连接上的消息屏障。
- 原版服务端命令生成实际电脑、修改手持物品、切换无线调试、配置和输出纳米机信息，并通过真实调试卡发送消息和剪贴板数据。客户端剪贴板命令、整段粘贴限制、冷却反馈和纹理选择器从正常入口执行。
- 航点自然 tick 产生真实粒子；机器人进入正常渲染。机器人标签开关使用实际配置重载，并保留绘制帧供核对。
- 测试客户端以原支持者 UUID 正常启动，通过真实玩家渲染和公开机器人渲染事件观察宠物与原颜色；隐藏开关使用实际配置和原可见性载荷。原支持者名单保持不变。
- 更新检查使用正常玩家登录、实际官方网络结果和本次进程的新缓存；当前只有 SDK 发布时验证不提示玩家更新，不制造 GitHub 响应或正向发行。
- 原版屏幕在缓冲区外释放鼠标时使用 DROP(-1,-1)。机器人和平板界面及其服务器输入校验恢复该专用哨兵，其他负坐标仍拒绝。合同通过实际机器人菜单、平板短按会话和公开 GUI 输入方法，观察底层真实 TextBuffer 的 touch/drop 信号；不构造替代菜单或输入上下文。

配置、剪贴板、相机及玩家位置/飞行状态在结束时恢复。

Windows 运行 [`client-effects-20261028-l1`](../build/api-compat-addon/integration-client/client-effects-20261028-l1/client-results.txt) 的自动报告整体为 **PASS**。实际外置驱动器插拔验证了独立的 500ms 冷却、15 格广播范围、方块声音分类与 1.5 音量；连接上的真实调试载荷确认范围外声音没有送达。命令、剪贴板、航点原生粒子、宠物颜色/可见性、Robot/Tablet 边界外松开，以及真实 GitHub 请求生成的新更新缓存均通过。宠物可见/隐藏两帧已目视确认，正常配置和渲染名单保持原值。

此前的机器人标签检查不足：`effects-particles-label-on.png` 和 `effects-label-off.png` 虽然拍到了机器人，但开启帧没有可见的 `C22 Robot Label`。原检查只证明机器人进入渲染器及配置被重载，因此当时没有据此关闭 C22，后续使用独立标签场景补验。

补充场景 `ocfixture.effectsFocus=labels` 只检查标签，不重复已通过的声音、命令、宠物和更新路径。它要求真实 `ClientLevel` 机器人的名字已经同步、实际 `Settings.robotLabels` 与请求值一致，再通过正常服务器传送稳定相机。正面和近距离俯视各保留开启、关闭两帧，以同一原生视角逐字比较字形对比度，并检查标签覆盖区域内的本体是否保持不透明；四张 PNG 均另行目视审阅。

`client-labels-20261028-l1` 确认实际名字、开启设置及相机位置后，标签锚点仍没有可见字形。对照原版 RobotRenderer 和本地官方 1.21.1 名牌渲染路径发现：移植代码使用现代 `cameraOrientation()`，但保留旧 GL 路径的 X 轴负缩放，使文字和背景转为背面并被原生字体渲染类型剔除。本批仅将 X 轴改为正缩放，与现代名牌的 `(+s,-s,+s)` 朝向一致，保留原大小、位置和开关行为。

使用新主包运行的 `client-labels-20261028-l2` 仍为 **FAIL**。实际 PNG 已能看到正向的 `C22 Robot Label` 及背景，说明朝向修复生效；但字形呈暗灰色，锚点内满足旧白色阈值的像素为 0，关闭帧未执行。该次结果没有用于闭合。后续场景固定真实世界为正午并记录原生光照，避免把环境亮度和显示缺陷混为一谈。

后续实际玩家近距离俯视时还出现标签遮去机器人本体、文字缺笔画。原 PIN 的名称在本体和工具之后绘制，背景先于字形，整个标签关闭深度写入；移植时却在本体之前提交原生 `Font.NORMAL` 字体及其内置背景，后者默认写深度，可能挡住随后提交的本体或字形。本批恢复本体/工具之后的标签顺序，并先单独画原黑色半透明背景，再提交不带内置背景的原生字形。标签的字体与背景使用各自原生渲染类型，仅在成对的状态设置/清理内设为 `COLOR_WRITE`，保留原深度测试、纹理、字体着色器和其他模型的缓冲；不全局清空缓冲，也不改全局着色器或深度状态。原距离、大小、锚点、开关、愚人节文本和移动偏移保持原行为。

修复后 Windows 运行 [`client-labels-20261028-m1`](../build/api-compat-addon/integration-client/client-labels-20261028-m1/client-results.txt) 整体 **PASS**。世界时间固定为 6000，实际原生光照为 15728640；真实机器人名称为 `Creatix`。正面约 3.2 格、近距离俯视约 0.98 格的开启/关闭对照均通过，七个字符各自有明确的字形对比度。俯视时标签覆盖区域中有 8358/13218 个本体像素与关闭帧保持一致，自动检查未出现原背景矩形挖空本体的模式。四张原生 PNG 已全部目视审阅：正面与俯视名称完整，关闭时名称消失，机体和箱体保持不透明，没有缺笔画或透出地面的孔洞。

C22 据此完成固定范围内验收：循环声复用 [`client-sound-20261027-h2`](../build/api-compat-addon/integration-client/client-sound-20261027-h2/client-results.txt)，磁盘声、命令、粒子、宠物、剪贴板、更新和边界外松开复用 [`client-effects-20261028-l1`](../build/api-compat-addon/integration-client/client-effects-20261028-l1/client-results.txt)，标签显示使用上述 m1 四帧及自动报告。此前 l1/l2 标签失败保留为修复前记录，未作为通过证据。远程传输与跨维度生命周期仍按独立 C19 范围记录。
