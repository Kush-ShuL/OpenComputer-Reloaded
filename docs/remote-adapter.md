# 多功能升级（MFU）

语义来源仅为 MightyPirates/OpenComputers 固定提交
`258943363ea8fc4ef14948e6bc6f67375061580c` 中的 `UpgradeMF.scala` 组件、物品与驱动，
以及 `BlockChangeHandler.scala` 和 `MFUTargetRenderer.scala`。保留上游许可证与归属。

MFU 是适配器专用的三级升级。服务端潜行右键记录目标方块、维度和点击面；未绑定、
绑定数据不完整或目标维度未加载时，驱动不创建环境。沿用五整数 `oc:coord`，现代
命名维度另存 `oc:dimension`，并读取主世界、下界和末地的原数字维度。物品保留绑定
提示及已保存节点的短地址。原物品和组件没有 Lua 回调，不新增回调。

有效连接要求同维度、目标所在区块已加载，并且目标方块中心至适配器宿主的距离
不超过 `misc.mfuRange`。节点保留不可寻址的能量连接器；每个 `power.tickFrequency`
周期扣除 `power.cost.mfuRelay × 周期刻数 × 中心距离`。

原生 OC 环境优先连接目标面的节点。该面没有节点时保持断开，不再把同一原生环境
交给外部驱动回退适配。普通目标通过注册的方块驱动创建环境，按原类名和
`oc:adapter.block` 中的 `name`、`data` 恢复状态；驱动改变时清除不适用的旧快照。
卸载远端环境遵循断开边、保存、移除节点的顺序，并提前清理内部引用，避免断连
回调重复保存或重新保留旧环境。目标替换、越界、区块卸载和升级移除均保留必要清理。

现代邻居通知事件覆盖快速更新，同时每刻核对目标，补足原 `notifyBlockUpdate` 能
观察而现代邻居事件遗漏的更新标志和方块实体替换。欠费后保持断开，直到下一次
扣能成功；目标通知不能绕过这一状态。当前远端环境仍按原 `canUpdate` 参与更新。

适配器共享入口已经改为先移除升级节点、再保存回物品；掉落前同样先执行卸载保存。
客户端已接入主手持 MFU 的绿色目标框与目标面显示，仅同维度且距绑定坐标不超过
64 格时显示，沿用原扩展 0.1 格、透明度 0.25 和穿墙效果；外观验收归 C20。

主模组 Windows 构建通过。NeoForge 21.1.224 批次 `device-batch-20261027-c3`
使用真实适配器、邻接 Case 与恰好三格远的原生屏幕，实际潜行绑定物品后插入升级，
两格空气之间的节点进入同一图。拔出物品后两图分离，原屏幕节点仍存活；升级保留
节点、绑定及 `oc:adapter.block` 保存记录，重新插入后恢复连接及原已入网节点身份。
未启动固件，也未使用虚构的宿主或 Context。
