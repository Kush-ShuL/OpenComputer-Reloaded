# Microcontrollers and tablets

Behavior is based on MightyPirates/OpenComputers commit `258943363ea8fc4ef14948e6bc6f67375061580c`: the original `common/{block,tileentity}/Microcontroller.scala`, `common/item/{Tablet,MicrocontrollerCase,TabletCase}.scala`, their item-data classes, `server/component/Tablet.scala`, `integration/opencomputers/DriverTablet.scala`, component inventory/computer/hub/rotation traits, and the dedicated menus/renderers. Existing registered resources and attribution remain in place.

The microcontroller retains a private machine/component graph, a powered snooper, five independently connected external plug graphs and the original per-side controller nodes. Network messages enter the private graph through a primary plug and leave through configured output sides; external graphs do not become machine-component networks. The front is excluded, its side callbacks distinguish invalid from unsupported sides, and analysis exposes the original exact face's controller node or the private machine node at the front. Per-side output flags and all existing cold-save identities remain preserved. Redstone sampling already performs local-direction conversion through the shared redstone state.

Microcontroller EEPROM exchange and tablet bay exchange now remove/save/install only the changed slot. The original construction and disposal lifecycle callbacks run for those real components, and initialization completes after the node graph is connected. Screens, keyboards, disks and other unchanged hardware keep their environment objects and open filesystem handles. The existing cold VM save/close path is retained. Cache invalidation which intentionally stops a tablet also commits component data after disconnection so closed filesystem descriptors are not reintroduced through the item.

Tablets keep their real machine while changing slots or moving to another holder in the same world. The previous holder's screen session closes; subsequent pitch/yaw and input use the current holder. World/dimension changes retain the existing save-and-recreate path. The tablet component's pitch/yaw callbacks retain their original non-direct scheduling and documentation. Its screen remains limited to 80×25 and four-bit color, and the dynamic last-slot bay retains its configured slot/tier restrictions and screen exclusion. The existing charger filesystem disconnect/remount fix is preserved; the tablet storage driver retains the original driver tier zero independently of the assembled tablet's item rarity.

The original charge bar remains visible, uses charge-dependent color and reads the actual saved/live capacity. Assembled tablet and microcontroller saves supply modern rarity components for their original tier colors. Tablet hardware tooltips use the configured sneak key, hide the built-in screen and preserve the original component heading. The assembled microcontroller has its original 64-item block-item limit and enchantment exclusion; its independently registered empty case items remain separate. The original short terminal use, sneak-stop/bay access and ten-tick analysis behavior remain, including the local completion tone using the existing speaker implementation.

Microcontrollers retain agent-owner interaction checks and synchronize their user list to client views. Their Forge Energy capability rechecks the current front face, including a capability obtained before rotation. Removal during a machine update no longer applies running properties to a replacement block. The existing explicit EEPROM menu is retained as a port convenience although the pinned version exchanged EEPROMs by sneak-use.

Existing evidence remains applicable: the separate-JVM native Lua 5.3 tablet/chest and assembled microcontroller save/resume checks cover VM stack/coroutine/userdata, storage offsets, EEPROM, identities, owner/orientation and side flags; the earlier power-device scenario covers charger tablet storage remount. `PortableDevicesContract` only adds finite real-host checks for the changed hot-swap, holder, callback and capability behavior. It does not repeat host/architecture matrices or substitute for shared Windows rendering/input and multiplayer acceptance.

The Windows dedicated-server report `build/api-compat-addon/devices/platform-20261027-g4/device-results.txt` records these individual passes:

- `portable.microcontroller`: real face callback errors, two normal EEPROM exchanges retaining returned data and unrelated component nodes, and an already obtained FE capability rejecting the actual front after rotation.
- `portable.tablet`: actual menu bay exchange retaining unchanged screen/keyboard/HDD environments and an open HDD writer, removed-disk descriptor closure, machine identity across hotbar selection and same-world holder transfer, current-holder pitch/yaw, and charge simulation/execution.
- `portable.expiry`: natural holder removal expires and disconnects the real tablet, saves closed component state, and recreates a stopped host with retained HDD bytes without reviving an old descriptor.

The report's overall `status=FAIL` belongs to other groups in that batch; the three portable results above are individually `PASS`. This finite SDK scenario does not boot firmware or repeat the existing native cold-save, charger-remount, routing or architecture evidence. Remote input, the local completion tone, Windows client visuals and multiplayer acceptance retain their shared validation boundaries.
